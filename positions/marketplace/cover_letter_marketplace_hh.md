# Сопроводительное письмо — AI-маркетплейс, Co-Founder / CEO

---

Вакансия с тремя такими вопросами — сама по себе хороший инструмент: она отсекает кандидатов-исполнителей и одновременно даёт срез того, как думают люди, претендующие на роль Co-Founder. Отвечу по существу, но часть позиции оставлю для разговора — принципиально, потому что реальная дискуссия продуктивнее письменного монолога.

**Какой самый сложный IT-продукт?**

VIZARD — платформа обеспечения безопасности мореплавания в Арктике. Сложность не в функциональности, а в архитектурной проблеме: система работает в real-time, цена ошибки — авария на буровой или потеря судна. Это потребовало формализовать границу автономности агента: что система решает сама, что предлагает оператору, что запрещено без явной санкции диспетчера — программно, не регламентом. Три слоя закрытия на случай деградации модели. SAR-пайплайн, edge-инференс на планшетах наблюдателей без выделенного GPU. Роль — Co-Founder / CTO: от архитектурного решения до production, 7 решений, клиенты — Газпром недра, Роснефть, Совкомфлот. Подробнее — на встрече.

**Amazon с AI 2026 — что принципиально иначе?**

Три разворота. Первый: убрать каталог как точку входа — заменить на conversational discovery, где LLM понимает намерение, а не ключевое слово. Второй: убрать отзывы как основной сигнал доверия — заменить на верифицированный поведенческий граф (что люди с похожим контекстом реально купили повторно, а не что написали). Третий: убрать централизованный склад как default — заменить на predictive pre-positioning по геокластерам спроса. Это меняет и unit-экономику, и скорость доставки одновременно. Детали архитектуры каждого из слоёв — на звонке.

**Три неэффективных архитектурных решения современных маркетплейсов?**

Первое: рекомендации на item-based collaborative filtering — работает на истории, игнорирует контекст сессии. Замена: multi-stage ranking с LLM-переранжировкой на последнем слое. Второе: поиск на инвертированном индексе без понимания запроса — пользователь формулирует намерение, а не термин. Замена: hybrid semantic + keyword с query understanding слоем перед retrieval. Третье: единая воронка для всех категорий — decision journey для электроники, одежды и продуктов питания принципиально разные, одна UX-логика ломает конверсию на каждой из них. Конкретные решения по каждому пункту — готов разобрать на встрече с примерами из практики.
